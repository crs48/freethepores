# Contributing

Useful contributions include research corrections, clearer explanations, accessibility improvements, and small technical fixes. No advertising or affiliate links.

## Research checklist

- [ ] Identify the exact claim or question being changed.
- [ ] Read and link the primary source; mark abstract-only access honestly.
- [ ] Include study design, population, outcome, and limitations where relevant.
- [ ] Distinguish measured results from an interpretation or a personal experience.
- [ ] Look for evidence that contradicts the proposed conclusion.
- [ ] Note funding or conflicts where known; never imply a full audit if none occurred.
- [ ] Keep new claims specific to the tested formulation and population.
- [ ] Preserve useful hygiene, sun protection, and medical-treatment context.
- [ ] Update source-check dates only for material actually rechecked.

## Development checklist

- [ ] Run `npm ci` using Node.js 22.12 or newer.
- [ ] Prefer typed data, pure functions, and declarative rendering.
- [ ] Use `href()` for internal links and assets so GitHub Pages paths work.
- [ ] Run `npm run validate`.
- [ ] Check affected routes on mobile and desktop, including keyboard navigation.
- [ ] Commit with a conventional title and descriptive bullets.

Keep pull requests focused. The source library's labels describe study types; they are not formal evidence grades. Changes to medical claims deserve explicit reasoning and links in the pull request description.
